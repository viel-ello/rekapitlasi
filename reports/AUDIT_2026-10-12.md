## 2. Ringkasan Eksekutif (Executive Summary)

### 2.1 Status Kesiapan Produksi (Production Readiness Assessment)
Aplikasi **Lumbung Data PKK Desa Belikurip** telah mengalami transformasi arsitektural yang sangat substansial dari prototipe awal level kecamatan (13 desa) menjadi sistem informasi berbasis dusun (9 dusun) dengan fitur operasional yang kaya: pelaporan Pokja I–IV, Rekapitulasi Dasa Wisma, Pemantauan Ibu Hamil/Melahirkan/Nifas/Kematian Balita, alur verifikasi approval berjenjang (Draft → Submitted → Approved → Locked), ekspor Excel multi-sheet Annex A–F, ekspor dokumen Word landscape, serta asisten cerdas Gemini AI dengan proteksi pratinjau dua tahap (*dry-run*).

Namun demikian, berdasarkan audit komprehensif lintas 8 aspek teknis, **aplikasi ini DINILAI BELUM SIAP UNTUK PRODUKSI PENUH (NOT PRODUCTION-READY)** sebelum **7 isu kritis penghambat (blockers)** diselesaikan. Terdapat kerentanan keamanan arsitektural fatal pada lapisan basis data, risiko penghapusan data masif akibat skrip reset operasional yang aktif, bug korupsi data pada fitur ekspor-impor Pokja II, serta kegagalan kompilasi/build pada sistem operasi Windows akibat file lock di cloud filesystem.

### 2.3 Tujuh Sorotan Risiko Paling Mendesak (Critical Blockers)
1. **[SEC-001 - Kritis] Database Row Level Security (RLS) Belum Aktif di Seluruh Tabel Supabase:**  
   Seluruh tabel PostgreSQL di Supabase tidak mengaktifkan RLS, sementara `NEXT_PUBLIC_SUPABASE_ANON_KEY` disematkan di browser client. Siapa pun dapat menggunakan anon key tersebut untuk memanggil PostgREST Supabase secara langsung, membaca tabel `users` (termasuk hash password), dan memanipulasi seluruh data PKK tanpa melewati autentikasi Next.js.
2. **[DB-001 - Kritis] Skrip Reset Operasional Memuat Perintah `TRUNCATE CASCADE` Aktif:**  
   File `supabase_reset_operational_data_to_zero_EXECUTE_MANUALLY.sql` memuat query `TRUNCATE TABLE ... RESTART IDENTITY CASCADE` yang **tidak diberi komentar**. Jika file ini dibuka di Supabase SQL Editor dan tidak sengaja tertekan tombol "Run", seluruh data operasional 9 dusun akan musnah seketika.
3. **[DB-002 - Kritis] Konflik Index Unik `data_umum_dusun_tahun_uidx` pada Penyimpanan Bulan ke-2:**  
   Migrasi v12 mengubah `data_umum` menjadi tabel bulanan (12 baris/tahun), namun skrip lupa men-drop unique index composite `(dusun_id, tahun)` dari migrasi v11. Akibatnya, input data umum pada bulan ke-2 dan seterusnya dipastikan gagal dengan error PostgreSQL: `duplicate key value violates unique constraint`.
4. **[DB-004 - Kritis] Kegagalan Agregasi Angka Tahunan pada Ekspor Excel:**  
   Pada `app/api/export/excel/route.js:72`, logika agregasi tahunan menggunakan pengecekan `if (typeof v === 'number')`. Sejak migrasi v6, seluruh kolom angka diubah menjadi `TEXT`. Kondisi ini selalu bernilai `false`, menyebabkan angka yang tercetak di Excel tahunan hanyalah data parsial bulan pertama, bukan total kumulatif 12 bulan!
5. **[FEAT-001 - Kritis] Pergeseran Kolom & Korupsi Data Pokja II pada Ekspor-Impor Excel:**  
   Ekspor Excel Pokja II menyisipkan kolom hantu `JML KLP PEMBACA` (`klp_pembaca`) di kolom 14 dan membuang kolom resmi `bkb_jml_ibu_peserta`. Ketika file hasil ekspor ini diimpor kembali ke aplikasi, terjadi pergeseran posisi data (*data corruption*) pada kelompok BKB di database.
6. **[TEST-003 / Dependensi - Kritis] Kerentanan RCE Next.js 16.2.5 pada Server Windows (GHSA-p293-qw3h-jr36):**  
   Paket `next@16.2.5` memiliki 1 kerentanan *Critical* Path Traversal RCE pada Windows-hosted server, exploit optimasi gambar AVIF, dan proxy bypass token filter. Diperlukan peningkatan segera ke `next@>=16.4.0`.
7. **[SEC-002 - Tinggi] Impor Excel Mem-bypass Period Lock:**  
   Endpoint `/api/import/confirm` tidak memvalidasi status penguncian periode (`checkPeriodLock`), memungkinkan operator atau kader menimpa data pada periode yang sudah berstatus `locked` melalui unggah file Excel.

- **Engine Build:** Next.js 16.2.5 (Turbopack) dengan React 19.2.4.
- **Hasil Eksekusi:** Terhenti / Timeout setelah 14+ menit berjalan tanpa menyelesaikan kompilasi (Task ID `task-18` dihentikan manual).

- **Analisis Akar Masalah (Root Cause):**
  1. **OneDrive Dehydration Timeout:** File biner native Rust SWC `next-swc.win32-x64-msvc.node` berada dalam direktori cloud OneDrive. Fitur *Files On-Demand* Windows memicu timeout saat Node.js mencoba memuat DLL biner tersebut.

  3. **Dual Lockfile:** Next.js mendeteksi lockfile ganda di parent path `C:\Users\ipw26\` yang berisiko menyebabkan miskonfigurasi root direktori Turbopack.

### 3.4 Evaluasi Pengujian E2E (Playwright) & Alasan Pembatalan
Pengujian E2E Playwright (`playwright.config.mjs`) **TIDAK DIJALANKAN (DIBATALKAN)** atas dasar kepatuhan keselamatan teknis berikut:

2. **Default `BASE_URL` Mengarah ke Lingkungan Live Produksi:**
   Pada `playwright.config.mjs:7`, default URL adalah:

   Suite `crud.spec.mjs` melakukan penulisan data uji tahun 2099 ke dalam database Supabase aktif. Hal ini secara tegas **melanggar Mandatory Safety Constraint #2** (Dilarang menulis/menghapus data pada DB produksi Supabase).

### 4.2 Analisis Pola Keamanan API
1. **Kepatuhan Desain Next.js App Router:** Tidak ada endpoint yang mengandalkan otorisasi layout client-side. Seluruh 45 rute mengimplementasikan pemeriksaan otorisasi mandiri di handler server.
2. **Pola Anti-Tamper Kader Dusun:** Pada seluruh operasi mutasi (POST manual, impor Excel, mutasi AI), server secara aktif menimpa payload input dengan `payload.dusun_id = user.dusun_id`. Upaya kader memanipulasi ID dusun lain ditolak secara konsisten dengan status 403 Forbidden dan dicatat pada audit log sebagai `permission_denied`.
3. **Pola Dry-Run AI yang Sangat Aman:** Endpoint `/api/chat` tidak memiliki hak tulis langsung ke database. Seluruh modifikasi data harus melalui `/api/chat/confirm-mutation` yang memverifikasi ulang hak akses JWT server-side, whitelist tabel/kolom, dan period lock.
4. **Celah Otorisasi yang Ditemukan:** Absennya pengecekan `checkPeriodLock` pada `/api/import/confirm` (`SEC-002`) menjadi satu-satunya celah bypass otorisasi operasional yang ditemukan pada lapisan route handler.

## 5. Daftar Temuan Baru Terstruktur Berdasarkan 8 Aspek

Setiap temuan telah diverifikasi secara independen terhadap codebase dengan bukti lokasi file dan baris yang valid.

### 5.1 Aspek 1: Keamanan (SEC)

#### [SEC-001] Database Row Level Security (RLS) Dinonaktifkan di Seluruh Tabel Supabase Sementara Anon Key Terekspos ke Client
- **ID:** `SEC-001`
- **Aspek:** Keamanan
- **Tingkat Keparahan:** **Kritis**
- **Lokasi:** `lib/supabase.js:19-25`, `supabase_schema.sql:1-120`, `supabase_schema_updates_v5.sql:1-200`
- **Deskripsi Masalah:** Seluruh tabel PostgreSQL di Supabase (`users`, `audit_logs`, `rate_limits`, `data_umum`, `data_pokja1-4`, `data_rekap_dawis`, `data_bumil`, `table_schemas`, `table_column_overrides`, `report_periods`) tidak memiliki konfigurasi `ENABLE ROW LEVEL SECURITY`. Di sisi lain, Next.js mengekspos `NEXT_PUBLIC_SUPABASE_URL` dan `NEXT_PUBLIC_SUPABASE_ANON_KEY` ke bundle browser client publik. Komentar di `lib/supabase.js:19-20` secara eksplisit mencatat: *"RLS tidak aktif pada tabel..."*.
- **Dampak:** Siapa pun dapat menyalin anon key dari DevTools/Network Tab, lalu mengirim request HTTP langsung ke PostgREST API Supabase (`https://<project>.supabase.co/rest/v1/...`). Penyerang dapat membaca hash password seluruh user, mengubah/menghapus data PKK, memanipulasi log audit, dan mem-bypass 100% proteksi Next.js (`proxy.js`, `requireAuth`, `canWriteRow`).
- **Rekomendasi Konkret:**
  1. Buat file migrasi `supabase_schema_updates_v14_enable_rls.sql` untuk mengaktifkan RLS pada seluruh tabel (`ALTER TABLE <nama_tabel> ENABLE ROW LEVEL SECURITY;`).
  2. Karena server Next.js menggunakan `service_role` (otomatis membypass RLS), blokir seluruh akses langsung role `anon` dan `authenticated` ke tabel sensitif. Izinkan `anon` hanya untuk `SELECT` pada view agregat publik dan tabel `dusun`.

#### [SEC-002] Impor Excel Mem-bypass Period Lock (`checkPeriodLock` Absen)
- **ID:** `SEC-002`
- **Aspek:** Keamanan
- **Tingkat Keparahan:** **Tinggi**
- **Lokasi:** `app/api/import/confirm/route.js:77`, `lib/excel/importToSupabase.js:126-132`
- **Deskripsi Masalah:** Saat periode pelaporan berstatus dikunci (`locked`), form input manual (`lib/api-handler.js:152`) dan mutasi AI (`app/api/chat/confirm-mutation/route.js:54`) memblokir penulisan data non-admin. Namun, endpoint konfirmasi impor Excel (`/api/import/confirm`) sama sekali tidak memanggil `checkPeriodLock`.
- **Dampak:** Operator atau kader dapat menimpa data pada periode yang sudah disetujui/dikunci oleh admin cukup dengan mengunggah file Excel, merusak integritas pelaporan resmi desa.
- **Rekomendasi Konkret:** Di `app/api/import/confirm/route.js`, periksa status periode sebelum mengeksekusi impor:
  ```javascript
  const { checkPeriodLock } = await import('@/lib/periodLock');
  for (const sheet of sheetsToImport) {
    const lock = await checkPeriodLock(sheet.table, targetYear, bulanValue);
    if (lock.locked && user.role !== 'admin') {
      return NextResponse.json({ error: `Periode ${targetYear} untuk ${sheet.sheetName} sudah dikunci.` }, { status: 403 });
    }
  }
  ```

#### [SEC-003] Kerentanan PostgREST Filter Injection pada Endpoint Audit Logs
- **ID:** `SEC-003`
- **Aspek:** Keamanan
- **Tingkat Keparahan:** **Tinggi**
- **Lokasi:** `app/api/admin/logs/route.js:42`, `app/api/admin/logs/export/route.js:46`
- **Deskripsi Masalah:** Parameter URL `dusun` atau `desa` disambung langsung ke dalam method `.or(...)` Supabase tanpa sanitasi:
  `query = query.or(`dusun_nama.eq.${unitNama},desa_nama.eq.${unitNama}`);`.
  Dalam sintaks PostgREST, karakter koma (`,`) adalah operator logika OR dan titik (`.`) adalah pemisah operator.
- **Dampak:** Pengguna admin (atau penyerang via CSRF) dapat menyuntikkan klausa filter sembarang (mis. `unitNama = 'Soko,id.gt.0'`) untuk memanipulasi kriteria query atau memicu database error yang mengekspos struktur internal.
- **Rekomendasi Konkret:** Validasi `unitNama` terhadap daftar resmi `DUSUN_LIST` atau bungkus nilai dalam tanda kutip ganda PostgREST setelah memvalidasi alfanumerik.

#### [SEC-004] Formula Injection / CSV Injection (CWE-1236) pada Ekspor Audit Log dan Ekspor Excel
- **ID:** `SEC-004`
- **Aspek:** Keamanan
- **Tingkat Keparahan:** **Tinggi**
- **Lokasi:** `app/api/admin/logs/export/route.js:16-21`, `app/api/export/excel/route.js:188, 278, 415, 505, 616, 914`
- **Deskripsi Masalah:** Pada ekspor CSV log audit dan sel teks bebas (seperti kolom `keterangan` hingga 1000 karakter pada ekspor Excel), teks pengguna ditulis mentah tanpa sanitasi terhadap karakter pemicu formula Excel (`=`, `+`, `-`, `@`, `\t`, `\r`).
- **Dampak:** Jika user memasukkan teks formula berbahaya (misal `=cmd|' /C calc'!A0` atau hyperlink eksfiltrasi data) pada keterangan data atau username, saat file dibuka oleh admin/auditor di Microsoft Excel, formula tersebut akan dieksekusi secara otomatis (DDE execution / data leak).
- **Rekomendasi Konkret:** Terapkan fungsi pembersih formula: jika teks diawali dengan `=,+,-,@,\t,\r`, tambahkan prefix tanda petik tunggal (`'`):
  ```javascript
  function sanitizeFormula(val) {
    if (val == null) return '';
    const str = String(val);
    return /^[=+\-@\t\r]/.test(str) ? `'${str}` : str;
  }
  ```

#### [SEC-005] Ekstraksi IP Rate Limiter Rentan Spoofing (`X-Forwarded-For`) & Fail-Open
- **ID:** `SEC-005`
- **Aspek:** Keamanan
- **Tingkat Keparahan:** **Sedang**
- **Lokasi:** `lib/rate-limit.js:17-23, 34-53, 60-88`
- **Deskripsi Masalah:**
  1. `getIP` mengambil elemen pertama dari `x-forwarded-for` tanpa memverifikasi apakah request berasal dari trusted reverse proxy. Penyerang dapat mengirimkan header palsu `X-Forwarded-For: <ip-acak>` pada setiap login gagal untuk mereset counter lockout.
  2. `checkRateLimit` bersifat fail-open: jika terjadi timeout database, fungsi mengembalikan `{ limited: false }`.
  3. `recordFailedAttempt` melakukan `SELECT` lalu `INSERT`/`UPDATE` terpisah tanpa atomic upsert, memicu race condition pada brute-force multi-threaded.
- **Dampak:** Bypass perlindungan brute-force login terhadap akun admin dan kader PKK.
- **Rekomendasi Konkret:** Di hosting Vercel, utamakan header terpercaya `x-real-ip` atau `x-vercel-forwarded-for`, dan gunakan atomic upsert `onConflict: 'ip'`.

#### [SEC-006] Regex Parsing Cookie `auth-token` Kurang Presisi
- **ID:** `SEC-006`
- **Aspek:** Keamanan
- **Tingkat Keparahan:** **Sedang**
- **Lokasi:** `lib/auth.js:173`
- **Deskripsi Masalah:** `getAuthUser` mengekstrak token menggunakan regex `cookieHeader.match(/auth-token=([^;]+)/)`. Tanpa anchor batas awal `(?:^|;\s*)`, jika header memuat cookie bernama lain seperti `bad_auth-token=xxx; auth-token=yyy`, regex akan mencocokkan nilai yang salah.
- **Dampak:** Potensi kegagalan autentikasi sesi (*Session DoS*) atau *Cookie Confusion*.
- **Rekomendasi Konkret:** Gunakan `request.cookies.get('auth-token')?.value` seperti di `proxy.js:17`, atau perbaiki regex menjadi `/(?:^|;\s*)auth-token=([^;]+)/`.

#### [SEC-007] Ketiadaan Rate Limiting pada Rute AI Chat, Ubah Password, dan Ekspor Dokumen
- **ID:** `SEC-007`
- **Aspek:** Keamanan
- **Tingkat Keparahan:** **Sedang**
- **Lokasi:** `app/api/chat/route.js:345`, `app/api/auth/password/route.js:11`, `app/api/export/excel/route.js:942`, `app/api/reports/build/route.js:112`
- **Deskripsi Masalah:** Rate limiting saat ini hanya aktif di `/api/auth` (login). Endpoint `/api/chat` (mengonsumsi kuota Google Gemini API), `/api/auth/password` (brute-force password lama), dan generator laporan dokumen berat tidak memiliki pembatas frekuensi request.
- **Dampak:**
  1. *Denial of Wallet*: Pengguna dengan role apa pun dapat membanjiri request ke Gemini AI hingga kuota API habis.
  2. *Denial of Service (DoS)*: Ekspor paralel file besar dapat menghabiskan RAM dan CPU instance serverless.
- **Rekomendasi Konkret:** Terapkan rate limiting per user ID: batasi `/api/chat` maks 15 req/menit, `/api/auth/password` maks 5 req/15 menit, dan `/api/reports/build` maks 10 req/menit.

#### [SEC-008] Inkonsistensi Atribut Cookie Logout & Ketiadaan Token Revocation Server-Side
- **ID:** `SEC-008`
- **Aspek:** Keamanan
- **Tingkat Keparahan:** **Rendah**
- **Lokasi:** `app/api/auth/route.js:77-81`, `app/api/auth/password/route.js:53-57`, `proxy.js:34`
- **Deskripsi Masalah:** Saat login, cookie disetel dengan `secure: true` (di prod) dan `sameSite: 'lax'`. Namun saat logout dan ganti password, cookie dibersihkan tanpa menyertakan atribut `secure` dan `sameSite`. Selain itu, token JWT bersifat stateless 24 jam tanpa session invalidation.
- **Dampak:** Pada browser tertentu, cookie logout mungkin tidak terhapus sempurna. Token lama tetap aktif selama 24 jam meskipun user telah mengganti kata sandi.
- **Rekomendasi Konkret:** Samakan atribut cookie saat clear token, dan tambahkan kolom `token_version INT DEFAULT 1` pada tabel `users` untuk membatalkan seluruh token lama saat rotasi password.

#### [SEC-009] Ketiadaan Jejak Audit pada Operasi Manajemen Pengguna
- **ID:** `SEC-009`
- **Aspek:** Keamanan
- **Tingkat Keparahan:** **Rendah**
- **Lokasi:** `app/api/admin/users/route.js:90-261`, `app/api/auth/password/route.js:11-63`
- **Deskripsi Masalah:** Penambahan user baru, perubahan role user, penghapusan user, dan penggantian password mandiri tidak memanggil `writeLog`. Selain itu, saat user dihapus di `admin/users:182`, `user_id` pada seluruh baris `audit_logs` diubah menjadi `NULL`.
- **Dampak:** Hilangnya jejak forensik terhadap aktivitas hak akses administratif.
- **Rekomendasi Konkret:** Tambahkan pemanggilan `await writeLog(...)` pada setiap mutasi pengguna di `admin/users/route.js` dan `auth/password/route.js`.

#### [PERF-003] Ketiadaan Index pada Kolom Filter Kritis (`tahun`) di Seluruh Tabel Operasional
- **ID:** `PERF-003`
- **Aspek:** Performa
- **Tingkat Keparahan:** **Tinggi**

- **Deskripsi Masalah:** Semua query data difilter dengan `WHERE tahun = $1`. Namun, index unik yang ada adalah composite dengan `dusun_id` di kolom pertama: `UNIQUE(dusun_id, tahun)`. - **Rekomendasi Konkret:** Buat index B-tree pada kolom `tahun` dan `(tahun, bulan)`:
  ```sql
  CREATE INDEX IF NOT EXISTS idx_data_umum_tahun_bulan ON data_umum(tahun, bulan);
  CREATE INDEX IF NOT EXISTS idx_data_pokja1_tahun ON data_pokja1(tahun);
  CREATE INDEX IF NOT EXISTS idx_data_pokja2_tahun ON data_pokja2(tahun);
  CREATE INDEX IF NOT EXISTS idx_data_pokja3_tahun ON data_pokja3(tahun);
  CREATE INDEX IF NOT EXISTS idx_data_pokja4_tahun ON data_pokja4(tahun);
  CREATE INDEX IF NOT EXISTS idx_data_rekap_dawis_tahun_bulan ON data_rekap_dawis(tahun, bulan);
  CREATE INDEX IF NOT EXISTS idx_data_bumil_tahun_bulan ON data_bumil(tahun, bulan);
  ```

#### [DB-003] Migrasi v4 Berisiko NO-OP Akibat CREATE TABLE IF NOT EXISTS Menimpa Skema v2
- **ID:** `DB-003`
- **Aspek:** Skema/DB & Migrasi
- **Tingkat Keparahan:** **Kritis**
- **Lokasi:** `supabase_schema_updates_v2.sql:43-52`, `supabase_schema_updates_v4.sql:7-21`
- **Deskripsi Masalah:** Skrip v2 membuat tabel `report_periods` tanpa kolom workflow. Skrip v4 mencoba mendefinisikan ulang tabel dengan kolom workflow (`status`, `submitted_by`, dll.) menggunakan klausul `CREATE TABLE IF NOT EXISTS`. Karena tabel sudah ada, statement v4 diabaikan (`NO-OP`).
- **Dampak:** Kolom `status` tidak pernah dibuat pada instance DB yang dimigrasi bertahap, menyebabkan error runtime saat modul approval diakses.
- **Rekomendasi Konkret:** Pastikan skrip perbaikan menambahkan kolom secara eksplisit: `ALTER TABLE report_periods ADD COLUMN IF NOT EXISTS status TEXT DEFAULT 'draft';`.

#### [DB-004] Agregasi Tahunan Excel Export Rusak Akibat Pengecekan `typeof number` pada Kolom TEXT v6
- **ID:** `DB-004`
- **Aspek:** Skema/DB & Migrasi
- **Tingkat Keparahan:** **Kritis**
- **Lokasi:** `app/api/export/excel/route.js:72`
- **Deskripsi Masalah:** Pada fungsi agregasi tahunan tabel bulanan:
  ```javascript
  if (typeof v === 'number') { existing[k] = (existing[k] || 0) + v; }
  else if (existing[k] == null) { existing[k] = v; }
  ```
  Sejak migrasi v6, seluruh kolom angka ber-tipe data PostgreSQL `TEXT`. Nilai yang diterima Node.js bertipe string (misal `"10"`). Pengecekan `typeof v === 'number'` selalu bernilai `false`, melompat ke blok `else if` yang hanya menyimpan angka bulan pertama!
- **Dampak:** Angka pada ekspor Excel tahunan tidak dijumlahkan, menghasilkan data yang salah secara fatal.
- **Rekomendasi Konkret:** Ganti pengecekan tipe dengan parsing numerik yang valid:
  ```javascript
  const num = Number(v);
  if (!isNaN(num) && v !== '' && v !== null) {
    existing[k] = (Number(existing[k]) || 0) + num;
  } else if (existing[k] == null) { existing[k] = v; }
  ```

- **ID:** `DB-005`
- **Aspek:** Skema/DB & Migrasi
- **Tingkat Keparahan:** **Tinggi**

#### [DB-006] Ketiadaan `ON DELETE SET NULL` pada `report_periods` Menghambat Penghapusan User
- **ID:** `DB-006`
- **Aspek:** Skema/DB & Migrasi
- **Tingkat Keparahan:** **Sedang**
- **Lokasi:** `supabase_schema_updates_v4.sql:14, 16`, `app/api/admin/users/route.js:182`

#### [DB-007] Privilege Escalation Otomatis pada Migrasi v9 untuk Role Sekretaris
- **ID:** `DB-007`
